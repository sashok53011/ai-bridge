# ai-bridge

AI-приставка: каталог AI-провайдеров, ключи на устройстве, статистика
от сообщества. Сервер — PocketBase на `app.devhorizon.online`, общий с прежним
Flutter-приложением; это приложение — Python: без компиляции, кросс-платформенное.

**Начни с [CONTEXT.md](CONTEXT.md)** — там всё, что нужно знать о продукте,
о сервере и о принятых правилах.

## Запуск

```powershell
uv sync                                     # зависимости
$env:AI_BRIDGE_EMAIL = "..."                # PowerShell
$env:AI_BRIDGE_PASSWORD = "..."
uv run python app.py                        # каталог с сервера и статистика
uv run python app.py --models ollama        # модели одного провайдера
uv run python app.py --check ollama         # проверить провайдера и отчитаться
uv run python app.py --pull ollama          # скачать модель (Ctrl+C — отмена)
uv run python app.py --enable ollama openai # включить провайдеров
uv run python app.py --disable ollama       # выключить
uv run python app.py --add "Мой LMS" http://127.0.0.1:1234/v1 qwen3-8b
uv run python app.py --remove moy-lms       # убрать: админу — в корзину, человеку — своё
uv run python app.py --serve                # локальный HTTP-сервис на :8080
```

`--add` делает разное в зависимости от входа: обычный пользователь
отправляет **предложение** (видят только он и администратор), админ
добавляет запись в каталог для всех. Ключ (`--key`) остаётся на
устройстве. id составляется из имени («Мой LMS» → `moy-lms`) или
задаётся через `--id`; приоритет по умолчанию — следующий свободный.

В Git Bash (или другом sh) то же самое, но иначе — и `cd` пишется
через слэши (`cd /e/android/ai-bridge`):

```bash
export AI_BRIDGE_EMAIL="..."
export AI_BRIDGE_PASSWORD="..."
uv run python app.py
```

Пароль можно положить в `config.toml` (копия `config.example.toml`) —
тогда export не нужен, и запуск работает из любого шелла; этот файл
в репозиторий не попадает.

## Локальный сервис

`--serve` открывает OpenAI-совместимый адрес — другие приложения ходят
в приставку, а она сама выбирает включённого провайдера, подставляет
ключ и, если провайдер отказал (включая 401/403 — плохой ключ одного
провайдера не повод падать), пробует следующего по приоритету.

Все `/v1/*` маршруты требуют **токен приставки** — свой, не провайдерский
(как в OpenRouter): клиент шлёт `Authorization: Bearer <токен>`, а настоящие
ключи провайдеров приставка подставляет сама. Токен создаётся при первом
запуске (`~/.ai-bridge/token`), показывается командой `--token`; для
чисто локального использования есть `--no-auth`.

`/v1/models` отдаёт **объединённый список**: настроенные модели включённых
провайдеров без префикса плюс все модели, которые провайдеры реально
отдают (с префиксом `провайдер/модель`) — откройте OpenWebUI или любой
OpenAI-совместимый клиент и увидите всё сразу.

```bash
uv run python app.py --serve                # слушает 127.0.0.1:8080
uv run python app.py --serve --port 9000    # свой порт
uv run python app.py --token                # токен приставки для /v1/*
uv run python app.py --serve --no-auth      # без проверки токена (только localhost!)
```

На том же порту открывается **страница приставки** (`http://127.0.0.1:8080/`) —
обычные формы, JavaScript не нужен:

- каталог с переключателями, статистикой и пометками (вкл / нераб. / ваш);
- кнопка «проверить» — итог и рост счётчика сообщества;
- ввод API-ключа (остаётся на устройстве, страница показывает только
  «задан/не задан»);
- добавление своего провайдера и удаление (админу — в корзину, человеку —
  своё предложение).

Страница защищена как положено локальной службе: при открытом доступе
чужой `Host` (DNS-rebinding) и чужой `Origin` (кнопки со страницы-обманки)
отклоняются; когда действует вход по токену, хост не проверяется —
настоящая защита там токен и `SameSite=Strict`. На не-loopback адресе
(`--host 0.0.0.0` для LAN/Tailscale) вход по токену включается сам;
за туннелем или прокси (которые достучатся до loopback) закройте
страницу флагом `--page-auth`.

## Доступ из интернета

Прокси уже умеет всё для этого: токен на `/v1/*`, вход на странице,
`--host 0.0.0.0`. Осталось дать ему адрес. Три пути, по убыванию
безопасности:

**1. Tailscale (рекомендую)** — не интернет, а ваша личная сеть поверх
него: шифрование, никаких открытых портов, ничего искать не надо.

```powershell
winget install tailscale          # на ПК и на телефон
tailscale up                      # войти по аккаунту
tailscale ip -4                   # например 100.101.102.103
uv run python app.py --serve --host 0.0.0.0
```

С телефона (в той же сети Tailscale): `http://100.101.102.103:8080/` —
форма входа, потом каталог; для OpenAI-клиентов тот же адрес + `/v1`
и токен из `--token`. Бесплатно для личного использования.

**2. Cloudflare Tunnel** — если нужен именно интернет и красивый адрес.
Бесплатный HTTPS на краю, входных портов нет (ПК сам стучится наружу).

```powershell
winget install cloudflared
cloudflared tunnel login            # выбрать домен devhorizon.online
cloudflared tunnel create ai-bridge
cloudflared tunnel route dns ai-bridge ai.devhorizon.online
```

В `~/.cloudflared/config.yml`:

```yaml
tunnel: ai-bridge
credentials-file: C:\Users\alex\.cloudflared\<id>.json
ingress:
  - hostname: ai.devhorizon.online
    service: http://127.0.0.1:8080
  - service: http_status:404
```

```powershell
cloudflared tunnel run ai-bridge
uv run python app.py --serve --page-auth   # страницу закрыть токеном!
```

HTTPS по краю означает, что токен летит по интернету зашифрованным.
`--page-auth` обязателен: туннель достучится до loopback, где вход
иначе выключен.

**3. Проброс порта роутера** — самый простой и самый рискованный.
Только вместе с HTTPS перед приставкой (Caddy, nginx) и только с токеном;
чистый HTTP отдаст токен открытым текстом. Для телефона по дороге
(кафе, оператор) — это реальная утечка. Если очень нужно быстро
попробовать — `ngrok http 8080` даст временный HTTPS-адрес без
настройки роутера.

Токен приставки равен вашей сессии PocketBase (суперпользо­ватель):
храните его как пароль, не показывайте в чатах и скриншотах.

```bash
curl http://127.0.0.1:8080/v1/models                       # модели включённых
curl http://127.0.0.1:8080/v1/chat/completions \
  -H "Authorization: Bearer $(cat ~/.ai-bridge/token)" \
  -d '{"model": "ollama/qwen3", "messages": [{"role": "user", "content": "привет"}]}'
```

Модель называется по-разному: «настроенная модель провайдера» (как в
каталоге) или «провайдер/модель» — `ollama/qwen3` отправит запрос в
Ollama с моделью qwen3, даже если она не настроена. Упавший провайдер
(429, 5xx, нет связи) уступает следующему; ошибка запроса (4xx) — не
повод переключаться, она уходит клиенту как есть. `Ctrl+C` останавливает
службу, оборвавшийся клиент — не ошибка и не traceback.

## Установка на Debian / FreedomBox

Приставка работает как системная служба рядом с PocketBase — каталог
доступен по `localhost`, консоль не нужна. Комплект в `deploy/debian/`:

```bash
# на сервере: код уже скопирован в /opt/ai-bridge
sudo bash /opt/ai-bridge/deploy/debian/install.sh   # 1-й прогон: шаблон секретов
sudo nano /etc/ai-bridge.env                        # вписать логин каталога
sudo bash /opt/ai-bridge/deploy/debian/install.sh   # 2-й прогон: служба работает
```

Установщик сам чинит CRLF-переносы (архив, собранный на Windows) и
создаёт служебного пользователя `ai-bridge`. Данные — в `/var/lib/ai-bridge`
(ключи, токен, снапшот), секреты — в `/etc/ai-bridge.env` (chmod 600).

Нюансы FreedomBox:

- **Порт по умолчанию 8080 может быть занят** (SearXNG из комплекта) —
  тогда поднимите службу на другом через drop-in
  `/etc/systemd/system/ai-bridge.service.d/port.conf` с `ExecStart=... --port 8095`;
  он переживает повторные прогоны установщика.
- **Брандмауэр — firewalld**: порт открывается в зоне **eth0 (external)**,
  а не internal (это wlan0-точка):

  ```bash
  sudo firewall-cmd --zone=external --add-rich-rule='rule family="ipv4" source address="192.168.0.0/24" port port="8095" protocol="tcp" accept' --permanent
  sudo firewall-cmd --reload
  ```

  Правило-источник ограничивает доступ вашей подсетью — даже при пробросе
  роутера наружу чужим будет отказ.
- **PocketBase рядом**: если он слушает `127.0.0.1:8090`, задайте
  `AI_BRIDGE_SERVER=http://127.0.0.1:8090` — без обхода через домен.
- **Каталог с LAN-адресами**: Ollama/LM Studio на другом ПК прописывайте
  по его адресу (`http://192.168.0.x:11434/v1`), не по `localhost` —
  для приставки «localhost» означал бы её же машину.
- **Переключатели суперпользо­вателя** живут только на устройстве: после
  установки включите нужных провайдеров командой `--enable` от
  служебного пользователя.

Журнал: `journalctl -u ai-bridge -f`. Токен: `app.py --token` (от
служебного пользователя, с `AI_BRIDGE_HOME=/var/lib/ai-bridge`).

## Что где

| Папка | Что внутри |
|---|---|
| `core/` | чистые функции: данные → данные. Ни сети, ни файлов, ни времени |
| `providers/` | HTTP: сервер каталога и сами провайдеры |
| `storage/` | ключи API в файле на устройстве |
| `app.py` | точка входа |
| `tests/` | pytest, файл на модуль |
