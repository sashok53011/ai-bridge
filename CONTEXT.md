# Контекст проекта

Этот файл — перенос знаний из старого проекта (`Login-Template`) в новый.
Читается целиком перед началом работы.

## 1. Зачем продукт

**AI-приставка**: приложение-посредник между другими приложениями и
AI-провайдерами. Пользователь держит каталог провайдеров (OpenAI, Anthropic,
Ollama, LM Studio, …), включает нужные, хранит свои API-ключи **на устройстве**
и проверяет, работает ли провайдер и какая модель у него есть.

Долгосрочная цель — чтобы другие приложения подключались к приставке и
пользовались её выбором провайдера. Поэтому форма «локальный HTTP-сервис»
(OpenAI-совместимый) важнее, чем форма «приложение с интерфейсом».

## 2. Из чего состоит система

| Часть | Технология | Где живёт |
|---|---|---|
| Сервер каталога | PocketBase (бинарник + JS-хуки) | **свой инстанс** `pb.devhorizon.online` (FreedomBox, `127.0.0.1:8091`); до 16.10.2026 — общий `app.devhorizon.online` |
| Старый клиент | Flutter (Dart) | Android-приложение — **не трогаем** |
| Старая веб-панель | HTML/JS/CSS | `https://app.devhorizon.online/ai-providers/` |
| **Новое приложение** | **Python** | **Эта папка — начало с нуля** |

Сервер **общий**: новое приложение ходит в тот же каталог и ту же статистику,
что и старое. Поэтому суперпользо­ватель видит свежие данные о популярности
и доступности от всех клиентов сразу.

## 3. Сервер PocketBase

Адрес: `https://pb.devhorizon.online` — **свой инстанс** на FreedomBox
(`127.0.0.1:8091`, служба `pocketbase-ai`, данные
`/home/sashok5301/pocketbase-ai/pb_data`, суперпользо­ватель — новый
аккаунт). До 16.10.2026 приставка ходила в общий каталог старого
проекта (`app.devhorizon.online`); тот инстанс остался прежнему
проекту и не трогается.

Марруты (реализованы в `deploy/pb_hooks/` старого проекта):

```
GET    /api/ai-config        -> { version, updated, canEdit, providers }
PUT    /api/ai-config        -> суперпользо­ватель: заменяет каталог;
                                обычный пользователь: сохраняет только переключатели
DELETE /api/ai-config        -> обычный пользователь: чистит свои переключатели
GET    /api/ai-config/meta   -> диагностика

GET    /api/ai-stats         -> статистика по всем провайдерам
POST   /api/ai-stats         -> отчёт о проверке: { providerId, model, ok, error }

GET    /api/ai-trash         -> корзина (только суперпользо­ватель)
POST   /api/ai-trash/restore -> вернуть из корзины
DELETE /api/ai-trash/{id}    -> очистить одну запись
DELETE /api/ai-trash         -> очистить корзину
```

Вход — под коллекцией `users` (`/api/collections/users/auth-with-password`),
ответ содержит `token`, который передаётся в заголовке `Authorization`
**без префикса Bearer**. Суперпользо­ватель входит через коллекцию
`_superusers` — тогда `canEdit = true`. Клиент пробует обе коллекции:
400 на `users` у админского аккаунта — это не опечатка, а место входа.

**PUT `/api/ai-config` у суперпользо­вателя заменяет каталог** (записи без
имени отбрасываются, отсутствующие уходят в корзину), поэтому флаги
«включён» ему отправлять нельзя — у админа сервер их и не хранит
(`viewFor({}, true, "")` всегда возвращает `enabled: false`). Переключатели
суперпользо­вателя — только на устройстве. Обычному пользователю PUT
принимает полные записи видимого списка: неотправленное стирается
(`writeFlags` заменяет файл), а незнакомые записи становятся его
предложениями.

## 4. Формат каталога

```json
{
  "version": 3,
  "updated": "2026-10-13T14:26:38.208Z",
  "canEdit": false,
  "providers": [
    {
      "id": "ollama",
      "name": "Ollama",
      "url": "http://localhost:11434/v1",
      "model": "llama3.2",
      "fallbackPriority": 10,
      "loginUrl": "",
      "getApiKeyUrl": "",
      "logoUrl": "",
      "logoAsset": "ollama",
      "status": "active",
      "origin": "admin",
      "authorId": "",
      "authorName": ""
    }
  ]
}
```

`id` — постоянный, по нему всё сходится; восстановление из корзины возвращает
запись **под тем же id**, и у людей подхватывается сохранённый ключ.

## 5. Статусы и правила синхронизации

| Статус | Поведение |
|---|---|
| `active` | обычная запись |
| `dead` | админ пометил как неработающую: **пользоваться можно**, но проверять нельзя, и она скрыта у тех, кто её не включал |
| `disabled_for_all` | выключена для всех: исчезает у всех; у включивших её раньше остаётся с пометкой и кнопкой «выключить» |

Правила, которые уже приняты и проверены:

- **Включённые человеком записи не удаляются никогда** — даже если каталог их
  больше не отдаёт. Человек включил сам — выключает сам.
- Выключенные берутся из каталога; помеченные `dead`/`disabled_for_all` в
  список не попадают.
- Удаление из каталога отправляет запись в корзину (восстановимо), но не
  трогает тех, кто включил.
- Предложения (`origin: "user"`) видит только автор и суперпользо­ватель;
  суперпользо­ватель публикует их на всех.

## 6. Статистика

Смысл показателя — **сколько человек смогли пользоваться**, а не сколько раз
проверяли. Формат хранения (по каждому провайдеру и модели):

```json
{
  "ollama": {
    "version": 1,
    "providerId": "ollama",
    "updated": "2026-10-13T14:26:38Z",
    "models": {
      "llama3.2": {
        "ok": 5, "fail": 2,
        "usersOk": 5, "usersFail": 2,
        "last": "2026-10-12T21:00:00Z",
        "lastStatus": "ok",
        "lastError": ""
      }
    }
  }
}
```

Человеку показывается как `5 (2) · 12.10 21:15` — успешно, с ошибками
(в скобках) и время последнего отчёта. Без отчётов — пустое место, ноль
показывать не нужно.

## 7. Безопасность — главное правило

**API-ключи никогда не покидают устройство.** Не на сервер, не в логи.
Серверу достаточно знать, что проверка прошла успешно (это и есть статистика).
Ключ живёт в хранилище приложения (на Android — защищённое хранилище,
в браузере — localStorage, в новом приложении — файл в домашней папке).

Операции, доступные только суперпользо­вателю: изменение каталога, публикация
предложений, корзина.

## 8. Провайдеры: два разных адреса

У провайдера **два корня**:

- список моделей — OpenAI-совместимый путь `<адрес каталога>/models`
  (обычно это `.../v1/models`);
- нативный API Ollama — в корне сервера: `POST /api/pull` (загрузка модели),
  `GET /api/tags`.

Пример: каталог даёт `http://localhost:11434/v1`, значит список моделей —
`http://localhost:11434/v1/models`, а загрузка — `http://localhost:11434/api/pull`.

Ответы на список моделей бывают двух видов:
`{"data": [{"id": "..."}]}` (OpenAI-совместимые) и `{"models": [{"name": "..."}]}` (Ollama).

## 9. Известные грабли

- **Ollama и браузер.** Запросы с веб-страницы блокируются, пока не прописано
  `OLLAMA_ORIGINS=https://app.devhorizon.online` (и перезапущен Ollama).
  Из приложений этой проблемы нет.
- **Адрес с телефона.** `localhost` на телефоне — это сам телефон. Для доступа
  к Ollama на ПК нужен его адрес в локальной сети (`http://192.168.0.x:11434/v1`);
  из эмулятора Android — `10.0.2.2`.
- **Ключ без заголовка.** Если ключа нет, заголовок `Authorization` не шлём
  вовсе: пустой `Bearer ` путает часть провайдеров.
- **401 без ключа — это не поломка**, а просьба ввести ключ. Поломка — это
  401 при уже введённом ключе.
- **Консоль Windows** по умолчанию cp1251: для русского текста нужно
  `sys.stdout.reconfigure(encoding="utf-8")`.
- **Суперпользо­вель и коллекция `_superusers`.** Вход админского аккаунта
  через `users` даёт HTTP 400 «Failed to authenticate» — это не поломка.
  Клиент пробует `users`, потом `_superusers`, и в ошибке оставляет обе
  причины.
- **Сообщение сервера важнее статуса.** PocketBase в отказах присылает
  `{"message": "..."}`; голый «HTTP 400» без него диагностику убивает.
- **Установка на Debian: CRLF.** `git archive` на Windows отдаёт файлы
  с `\r\n`, а bash на Debian читает «pipefail\r» как неизвестную опцию.
  Установщик сам себя перезапускает с очищенными переносами.
- **FreedomBox: зоны firewalld.** `internal` — это wlan0-точка, а LAN-порт
  (`eth0`) числится в `external`. Порт службы открывается правилом-источником
  в `external`, иначе снаружи тайм-аут при `policy accept` в iptables.
- **PocketBase-хуки знают только свои поля.** И `sanitize` (запись), и
  `viewFor` (ответ GET) собирают объекты поля-за-полем: новое поле
  каталога молча отбрасывается на обоих концах. Добавление поля — правка
  обоих хуков + перезапуск pocketbase; старые клиенты поля игнорируют.
- **Админская запись заменяет каталог целиком.** Правка/добавление/удаление
  шлют PUT со всем каталогом — база для списка всегда **свежий** GET
  с сервера (service/ops.py). Пустой или устаревший список унёс бы чужие
  записи в корзину: так 16.10.2026 страница потеряла каталог за одну
  правку. Регрессия — в tests/test_webui.py (TestAdminWritesKeepCatalogue).
- **FreedomBox: `sudo -u` сбрасывает окружение.** Для запуска от
  служебного пользователя с секретами — root читает `/etc/ai-bridge.env`
  и передаёт через `runuser -u ai-bridge -- env ...`.
- **PocketBase-хуки** в старом проекте изолированы и не видят верхнюю область
  файла; ошибки хуков пишутся в `pb_data/auxiliary.db`, а не в журнал.

Фоновая автопроверка (`--check-interval`, внутри `--serve`) проверяет
включённых по расписанию и сама отчитывается в статистику сообщества;
ключи на устройстве зашифрованы: `master.key` рядом с `keys.json`
(на Windows — привязан к учётной записи через DPAPI). Потеря
`master.key` — потеря ключей, ошибка об этом говорит прямо.

Проверено на живом сервере: вход (включая суперпользо­вателя через
`_superusers`), каталог (29 провайдеров), список моделей локального Ollama
(11 моделей), поток загрузки модели (`pulling manifest` → слои с процентами →
`success`), полная загрузка `qwen3:0.6b` через `--pull`, переключатели
`--enable/--disable` (для суперпользо­вателя — локально, флаг переживает
перезапуск). Счётчик статистики показывается колонкой в каталоге; `--check`
отправляет отчёт и показывает свежий счётчик сообщества.

Локальный сервис (`--serve`) проверен вживую: `/v1/models` отдаёт модели
включённых; чат через `ollama/qwen3:0.6b` дошёл до Ollama и вернул ответ
(шлюз подставляет чистое имя модели); SSE-поток идёт кусками до `[DONE]`;
оборвавшийся клиент — одна строка в журнале вместо traceback.

`--add`/`--remove` проверены вживую (вход суперпользо­вателем): запись с

Страница (`--serve`) проверена вживую: каталог с пометками и статистикой
отдаётся на `/`, тумблер переключает флаг через полный путь (POST →

Токен и объединённые модели проверены вживую: `--token` печатает токен

**Аккаунты и личные пространства (этап 1 мультипользовательской
версии).** Страница требует входа со всех адресов: логин/пароль
аккаунта сервера каталога, регистрация **открыта** (защита — модерация
админа на `/users`), аварийный вход — токен устройства (он же личный
`/v1`-токен админа, OpenWebUI не заметил изменений). Личное пространство:
у хозяина (суперпользо­вателя) ключи и переключатели живут в корне
устройства, у остальных — в `users/<id>/`; ключи шифруются общим
мастер-ключом. Человеку доступно: свой ключ, проверка (отчёт уходит
**под его именем** — хуки `ai-stats` уважают `userId` от суперпользо­вателя),
выбор своей модели, тест-чат (крошечный платный запрос, `max_tokens=16`),
свои `/v1`-токены (создать/отозвать на `/tokens`). Гейтвей персональный:
токен человека → его переключатели и его ключи. Админ дополнительно:
правки каталога, добавление/удаление, список людей с удалением
(аккаунт на сервере + личное пространство + токены + сессии).
`--page-auth` больше не нужен: вход обязателен всегда.

## 11. Правила разработки

1. **Чистое ядро.** В `core/` — только функции «данные → данные». Ни сети,
   ни файлов, ни времени. Всё, что снаружи, — в `providers/` и `storage/`.
2. **Тест на стадии отладки.** Нашёл баг — сначала пишешь воспроизводящий
   тест на реальных данных из логов, потом чинишь. Тест остаётся как регрессия.
3. **Быстрая проверка.** `uv run pytest` — офлайн, ~250 тестов, ~20 с.
   Тесты по одному файлу: `uv run pytest tests/test_catalogue.py`.
4. **UI в конце.** Интерфейс добавляется, когда известен весь набор функций,
   а не после каждой мелочи.
5. **Секреты — только в окружении.** В репозиторий не попадают ни пароли,
   ни ключи (`config.toml` в `.gitignore`).

## 12. Команды

```bash
uv sync                     # поставить зависимости
uv run pytest               # прогнать все тесты
uv run python app.py        # каталог с сервера и статистика
uv run python app.py --models ollama
uv run python app.py --check ollama   # проверка + отчёт статистики
uv run python app.py --pull ollama    # скачать модель (Ctrl+C — отмена)
uv run python app.py --enable ollama  # включить (локально; обычный — и на сервер)
uv run python app.py --disable ollama # выключить
uv run python app.py --add "Мой LMS" http://127.0.0.1:1234/v1 qwen3-8b
uv run python app.py --remove moy-lms # убрать: админу — в корзину, человеку — своё
uv run python app.py --set-model ollama qwen3:0.6b  # модель по умолчанию
uv run python app.py --edit ollama context=128K pricing='$0.1/1M' capabilities='vision, tools'
uv run python app.py --serve          # служба: API на :8080/v1 + страница на :8080/
uv run python app.py --token          # токен приставки (для /v1/* и страницы на LAN)
uv run python app.py --serve --host 0.0.0.0 --page-auth  # доступ из LAN/Tailscale
uv run python app.py --serve --check-interval 0  # без фоновой автопроверки
```

Логин: переменные `AI_BRIDGE_EMAIL` и `AI_BRIDGE_PASSWORD`
(или поля `email`/`password` в `config.toml`, который в репозиторий не идёт).
